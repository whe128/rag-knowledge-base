# BM25

## What is BM25?

BM25 is a classical lexical information retrieval algorithm.

Unlike dense retrieval, BM25 does not represent documents using neural embedding vectors. Instead, it evaluates the relevance between a query and a document based primarily on the occurrence and importance of query terms.

BM25 considers several factors, including:

- Term frequency
- Inverse document frequency
- Document length normalization

## Term Frequency

Term frequency describes how often a query term occurs in a document.

If an important query term occurs multiple times in a document, that document may be considered more relevant.

However, simply counting the number of occurrences is not sufficient because extremely long documents may naturally contain more terms.

BM25 therefore applies a saturation effect to term frequency.

## Inverse Document Frequency

Inverse document frequency measures how informative a term is across the document collection.

A common word appearing in many documents provides less information.

A rare technical term appearing in only a few documents is more informative.

For example, in a technical knowledge base, the term "reranker" may be more useful for identifying relevant documents than a common word such as "system".

## Document Length Normalization

BM25 also considers document length.

Without length normalization, long documents could receive an unfair advantage simply because they contain more words.

BM25 therefore adjusts its score according to document length.

## Strengths of BM25

BM25 is particularly effective for queries containing:

- Exact technical terms
- Names
- Identifiers
- Product names
- Rare keywords
- Specific phrases

For example, if the query is:

"What is Reciprocal Rank Fusion?"

BM25 can benefit from the exact occurrence of the phrase "Reciprocal Rank Fusion".

## BM25 versus Dense Retrieval

BM25 relies primarily on lexical matching.

Dense retrieval relies on semantic similarity between embedding vectors.

For example:

Query:
"How does lexical retrieval rank documents?"

A dense retriever may retrieve a document discussing:

"BM25 evaluates documents using term frequency and inverse document frequency."

BM25 may perform better when important keywords appear exactly in the relevant document.

Dense retrieval may perform better when the query and document use different wording but express the same concept.

## BM25 Tokenization

BM25 operates on tokens.

A simple implementation may lowercase text and split it using whitespace.

For English text, this simple strategy can work reasonably well.

For Chinese text, whitespace tokenization is often insufficient because Chinese words are not normally separated by spaces.

A Chinese BM25 implementation may therefore require word segmentation or character-level tokenization.
